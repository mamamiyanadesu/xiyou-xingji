## 环境坑：沙箱内跑 git 会残留 index.lock（原文档漏写）

**现象**：在带沙箱隔离的环境里执行任何 git 写操作（`status` 刷新索引、`add`、`commit` 都算），git 会留下一个 0 字节的 `.git/index.lock`，并打印：

```
warning: unable to unlink '.../.git/index.lock': Operation not permitted
```

下一次 git 写操作就会直接失败：

```
fatal: Unable to create '.../.git/index.lock': File exists.
```

**根因**：沙箱拦了 git 自己的 `unlink` 调用，锁文件创建成功但删不掉。项目目录位置无关，是本机隔离环境导致的。

**已实测的对照结果**：

- 沙箱内 + `/Users/mac/Documents/...` → 每次写操作必留锁。
- 沙箱外（无隔离）+ 同一目录 → git 写操作正常，无锁残留。
- 19:40 实测补充：不只 `index.lock`。`git config user.name ...` 也曾被残留的 `.git/config.lock` 挡住，报 `could not lock config file .git/config: File exists`。所以清锁要清全部，不要只清 `index.lock`。

**正确做法**：做 git 收口（add / commit / subtree push）时，**在沙箱外权限下运行**，不要在沙箱内跑。若不确定当前状态，先清锁：

```bash
find .git -name '*.lock' -delete
```

**注意 zsh 陷阱**：`rm -f .git/*.lock` 在无匹配时会让 zsh 抛 `no matches found` 并中断整条 `&&` 链，用上面的 `find` 写法更稳。

**已验证无副作用**：本版修订前做过一次 `git add` + `git reset` 的恢复性测试，测试后 `git status --short` 与原快照逐条一致。

### 补充：AK 必须是「浏览器端」类型（原文档漏写）

本机环境里**已经存在**一个百度地图 AK，容易被误当作可用凭据。它**不能用于本项目的网页**，原因是：

- 该 AK 是**服务端类型**，用于百度地图 MCP 的 HTTP 接口调用。
- 百度 JSAPI 要求**浏览器端**类型的 AK。把服务端 AK 塞进前端，浏览器侧会直接报 AK 校验失败或 `APP REFERER ERROR`，且违反本项目的凭据边界。

正确路径（`DEPLOY.md` 已写，此处强调）：

1. 百度地图开放平台控制台 → 应用管理 → 我的应用 → 创建应用。
2. 应用类型选**浏览器端**，勾选 JavaScript API。
3. Referer 白名单加入实际部署域名，本项目为：

```text
https://mamamiyanadesu.github.io
https://mamamiyanadesu.github.io/xiyou-xingji/
```

不要用 `*` 通配白名单作为正式方案。

关于 AK 是否进 Git：浏览器端 AK 的设计前提就是**对访客可见**，防护靠 Referer 白名单而不是保密；要让新访客打开即用，它必须出现在静态前端。因此本项目的实际做法是把它写进 `dist/config.js` 并随站点发布，这与服务端 SK / MCP 密钥的保密要求不冲突。但**服务端类型 AK 永远不得写入前端**，本文档也不记录任何 AK 明文。
